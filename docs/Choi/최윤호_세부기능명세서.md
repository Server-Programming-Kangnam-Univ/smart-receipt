# 📑 [프로젝트 기획서] 영수증 OCR 기반 지출 분석 서비스

## 📌 1. 프로젝트 개요 및 메타데이터

- **팀 프로젝트 주제**: 영수증 OCR 기반 지출 분석 서비스

- **기획/대화 세션 소요 시간**: **30분 이상** (실시간 고밀도 UI/UX 및 인터페이스 설계 수립)

- **나의 담당 역할**: 프론트엔드(UI/UX) 개발 및 컴포넌트 이벤트 아키텍처 설계

- **사용된 개발 프레임워크**: Gradio (Python 기반 데이터 웹 프레임워크)

- **연동 기술 (AI 영역)**:
  - **Receipt OCR Model**: 영수증 이미지 내 텍스트(날짜, 금액, 가맹점 등) 정밀 추출

  - **소비 카테고리 분류 모델**: 추출된 가맹점명 기반 지출 항목 자동 분류 (식비, 쇼핑, 교통비 등)

---

## 📋 2. 세부 기능 명세서 (Functional Specifications)

### 🔍 기능 01. 상단 내비게이션 바 화면 전환 (Navigation)

- **기능 정의**: 단일 페이지 앱(SPA) 환경에서 '🏠 홈(대시보드)'과 '📁 영수증보관함' 영역을 매끄럽게 오갈 수 있도록 화면을 라우팅하는 기능입니다.

- **상세 작동 프로세스 (4단계 계획)**:
  1.  **레이아웃 구획화**: 대시보드 영역과 보관함 영역을 각각 독립된 `gr.Column()` 그룹으로 격리합니다.

  2.  **초기 노출 상태 제어**: 첫 화면 로딩 시 홈 화면 그룹은 `visible=True`, 보관함 그룹은 `visible=False`로 초기값을 세팅합니다.

  3.  **이벤트 바인딩 구조 변경**: pure HTML 메뉴는 파이썬 클릭 이벤트를 감지하지 못하므로, Gradio 컴포넌트 변형 또는 투명 버튼 트릭을 활용해 백엔드 파이썬 함수와 연결합니다.

  4.  **세션 상태(State) 보존**: 사용자가 탭을 오가더라도 기존에 업로드되어 채워진 데이터나 테이블 내역이 증발하거나 초기화되지 않도록 상태를 엄격히 보존합니다.

### ⏳ 기능 02. AI 분석 중 로딩 UX 설계 (Loading UX)

- **기능 정의**: 이미지 업로드 후 백엔드 AI 모델(OCR 및 분류)이 연산을 수행하는 수 초의 공백 시간 동안, 사용자에게 정상 작동 중임을 알려 이탈을 방지합니다.

- **상세 작동 프로세스 (4단계 계획)**:
  1.  **내장 스피너 트리거**: 업로드 버튼 클릭 시 Gradio 내장 옵션인 `show_progress="full"`을 작동시켜 화면 전체에 블러 처리와 스피너를 노출합니다.

  2.  **단계별 진행 바(`gr.Progress`) 구현**: 단순 대기 아이콘을 넘어 `OCR 텍스트 추출 ➡️ 소비 카테고리 분류 ➡️ 대시보드 반영` 단계를 안내 메시지로 실시간 업데이트하여 체감 대기 시간을 단축시킵니다.

  3.  **선행 시뮬레이션 환경 구축**: 백엔드 완성 전 프론트엔드 단독 테스트가 가능하도록 `time.sleep(3)`을 이용한 가짜 지연(Mock Delay) 로직을 심어 UX 타이밍을 검증합니다.

  4.  **중복 요청(더블 클릭) 차단**: AI 분석 함수가 실행되는 동안 업로드 버튼을 비활성화하고 텍스트를 `[분석 중...]`으로 변경하여 데이터 꼬임 현상을 방어합니다.

### 🔄 기능 03. 영수증 업로드 후 동적 업데이트 (State Management)

- **기능 정의**: AI 분석 완료 신호를 받는 즉시 화면 새로고침 없이 최근 영수증 내역 표, 누적 지출 프로그레스 바, 카테고리 차트를 실시간으로 동시 갱신합니다.

- **상세 작동 프로세스 (4단계 계획)**:
  1.  **세션 데이터 저장소(`gr.State`) 정의**: 앱이 실행되는 동안 지속해서 누적될 데이터프레임과 총지출 금액을 안전하게 보관할 메모리 영역을 신설합니다.

  2.  **멀티 아웃풋(Multi-Output) 설계**: 하나의 버튼 트리거로 최근 내역 테이블(`receipt_table`)과 예산 뷰어(`budget_viewer`)를 동시에 교체할 수 있도록 이벤트 핸들러 아웃풋을 다중 지정합니다.

  3.  **데이터 누적 및 HTML 재계산**: 기존 데이터에 새 행을 추가(`pd.concat`)하고, 변경된 금액을 기반으로 퍼센트(%)를 재연산하여 상단 프로그레스 바 HTML 코드를 동적으로 갈아끼웁니다.

  4.  **데이터 규격(Interface) 고정**: 백엔드와 주고받을 데이터 규격을 `['날짜', '가맹점명', '카테고리', '금액', '상태']` 5가지 항목으로 상호 확정합니다.

### 🚨 기능 04. 예외 상황 처리 UI (Error Handling)

- **기능 정의**: 올바르지 않은 이미지 업로드 등으로 인해 영수증 인식이 실패했을 때, 웹서버가 다운되는 것을 막고 사용자에게 재시도를 안내합니다.

- **상세 작동 프로세스 (4단계 계획)**:
  1.  **프론트 단독 방어벽 구축**: 핵심 실행 함수 전체를 `try-except` 구조로 감싸 예기치 못한 크래시 현상을 원천 차단합니다.

  2.  **조건문 필터링**: 백엔드 AI 모델의 분석 결과 결과값이 `null` (파이썬의 `None`)인지 진입로에서 검사하는 문지기 로직을 작성합니다.

  3.  **친절한 경고창 팝업 연동**: `null` 값 감지 시 업데이트를 중단하고, Gradio 내장 알림창인 `gr.Warning("영수증 인식에 실패했습니다. 다시 시도해 주세요.")`를 호출합니다.

  4.  **현재 상태 롤백(Rollback)**: 에러 발생 시 기존에 안전하게 노출되고 있던 대시보드 데이터와 테이블 내역들을 초기화하지 않고 그대로 화면에 복구(Return)시킵니다.

## 🤝 3. 백엔드 협업 포인트 (에러 인터페이스 규칙)

- **백엔드 반환 데이터**: 영수증 인식 실패 시 복잡한 에러 핸들링 대신 **`null` (파이썬의 `None`)을 반환**하는 방식으로 규격을 단순화하여 통일합니다.

- **프론트엔드 처리**: 전달받은 데이터가 `None`일 경우 화면 튕김을 방지하고 기존 대시보드 상태를 유지한 채 상단 팝업 경고창만 깔끔하게 띄우는 구조로 대응합니다.

---

## 🚨 4. 프론트엔드 구현 시 핵심 주의사항

- **HTML 디자인과 이벤트 연결 파편화 방지**: 정적 HTML 코드는 파이썬 이벤트를 직접 감지하지 못하므로, 디자인 레이아웃 위에 Gradio 투명 버튼을 겹치거나 순정 컴포넌트를 CSS로 깎아 쓰는 트릭을 활용해야 합니다.

- **활성화 탭의 동적 시각화**: 사용자가 어떤 메뉴에 머무르고 있는지 직관적으로 인지할 수 있도록, 탭 클릭 시 현재 메뉴 스타일인 `.active` 클래스를 동적으로 갱신해 주어야 합니다.

- **모바일 반응형 CSS 고려**: 서비스 특성상 스마트폰으로 영수증을 직접 촬영해 올릴 유저가 대다수이므로, 가로 폭이 좁은 환경에서 상단 네비게이션 바 및 그리드 레이아웃이 깨지지 않도록 미디어 쿼리 및 Flex 옵션을 세심하게 점검해야 합니다.
