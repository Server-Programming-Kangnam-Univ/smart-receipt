| **담당 역할**        | 프론트엔드 UI 개발 (Gradio 기반 대시보드 및 웹 인터페이스 구현) |

## 1. 생성형 AI와의 대화 요약

생성형 AI(Gemini)와 약 30분간 대화하며, FastAPI 및 Groq API 백엔드와 연동할 Gradio 기반의 웹 UI 설계 및 프론트엔드 아키텍처를 구체화하였다.

### 대화 흐름 요약

**[1단계] UI 프레임워크 선택 및 레이아웃 정의**

- 백엔드(FastAPI)와의 빠른 연동과 프로토타이핑을 위해 `Gradio(gr.Blocks)`를 메인 UI 프레임워크로 선정.
- 정형화된 기본 Gradio 템플릿을 벗어나, 실제 상용 웹 서비스 느낌을 주기 위해 상단 네비게이션 바, 메인 대시보드 그리드, 하단 데이터 테이블의 3단 레이아웃 구조를 설계함.

**[2단계] Custom CSS를 통한 대시보드 컴포넌트 고급화**

- Gradio의 한계를 극복하기 위해 `custom_css` 문자열을 주입하여 스타일링 최적화.
- 카드 레이아웃(`.dashboard-card`), 모던 내비게이션 바(`.navbar`), 부드러운 배경색 등을 반영하여 시각적 완성도를 높이는 방향으로 조율.

**[3단계] 예산 대비 지출 시각화(프로그레스 바) 설계**

- 정적 텍스트 대신 사용자가 직관적으로 소비 현황을 볼 수 있도록 HTML과 CSS를 결합한 동적 프로그레스 바 함수(`get_budget_html`) 구현 논의.
- 총 예산 대비 누적 지출액을 퍼센트(`%`)로 계산하여 바 너비(`width`)에 실시간 반영하는 구조 확정.

**[4단계] 소비 패턴 시각화 및 데이터 구조화**

- 카테고리별 소비 비율을 직관적으로 보여주기 위해 `gr.Label` 컴포넌트를 활용하여 파이차트 형태의 데이터 탑승 구조 배치.
- 최하단에는 최근 업로드한 영수증 내역을 5개 컬럼(`날짜`, `가맹점명`, `카테고리`, `금액`, `상태`)의 `gr.Dataframe`으로 구조화하여 배치하기로 결정.

**[5단계] 인터랙션 및 예외 처리 흐름 정의**

- 새 영수증 올리기 버튼(`upload_btn`) 클릭 시 백엔드로 이미지 데이터를 전달할 통로로 숨김 처리된 `gr.Image` 컴포넌트(`visible=False`)를 연동하는 트릭 및 흐름 확정.

## 2. 담당 세부 기능 명세서

### 2.1. 대시보드 레이아웃 및 커스텀 스타일링 (UI/UX)

Gradio의 `gr.themes.Soft()` 테마를 기반으로, 비즈니스 대시보드에 적합한 사용자 정의 CSS(`custom_css`)를 자원화하여 적용.

- **상단 네비게이션 바 (`.navbar`):** 서비스 로고(🧾 영수증 AI)와 메뉴 항목을 배치하여 웹 앱 형태의 아이덴티티 부여.
- **AI 소비 리포트 카드 (`.report-card`):** Groq API가 분석한 자연어 요약 문구가 가독성 높게 노출되도록 별도 푸른색 계열 블록으로 강조.
- **공통 카드 스타일 (`.dashboard-card`):** 각 대시보드 위젯들을 독립된 그리드로 분리하고 그림자(box-shadow)와 테두리 라운딩 처리로 모던한 UI 연출.

---

### 2.2. 실시간 소비 현황 위젯 및 데이터 시각화

1. **동적 누적 지출 프로그레스 바**
   - 백엔드에서 넘겨받은 `spent`(지출액)와 `total`(예산) 데이터를 기반으로 퍼센트를 계산하는 파이썬 함수 연동.
   - 예산이 0원일 때의 제로 디비전(ZeroDivision) 예외 처리를 포함하여 컴포넌트 안정성 확보.
   ```python
   def get_budget_html(spent=300000, total=10000000):
       if total == 0: percent = 0
       else: percent = int((spent / total) * 100)
       return f"... style='width: {percent}%;' ..."
   ```

```

2. **카테고리별 소비 비율 피드백 (`gr.Label`)**
* 백엔드(FastAPI + Groq)에서 분류한 `식비`, `Shopping`, `교통비`, `기타` 등 핵심 카테고리 데이터를 딕셔너리 형태로 받아와 상위 소비 항목 비율을 차트 형태로 매핑.



---

### 2.3. 영수증 내역 관리 및 이미지 데이터 업로드 파이프라인

1. **최근 업로드 내역 테이블 (`gr.Dataframe`)**
* 사용자가 과거에 올린 영수증 처리 상태를 한눈에 볼 수 있도록 `interactive=False` 옵션의 고정형 5열 테이블 구성.
* 초기 로딩 시 데이터 공백으로 인한 UI 깨짐을 방지하기 위해 `initial_data` 구조 선언.


2. **비동기 이미지 업로드 인터랙션**
* UI 레이아웃을 해치지 않기 위해 실제 이미지 컴포넌트(`gr.Image`)는 `visible=False`로 은닉.
* `+ 새 영수증 올리기` 버튼 클릭 이벤트와 히든 이미지 컴포넌트를 트리거하여 사용자가 파일을 선택하는 즉시 백엔드 분석 파이프라인(FastAPI Endpoint)으로 이미지 스트림이 전달되도록 이벤트 바인딩 기반 마련.

## 3. 팀원과의 협업 포인트

| 협업 대상 | 내용 |
| --- | --- |
| **백엔드 (FastAPI)** | - 사용자가 영수증 업로드 시 히든 `gr.Image`로 들어온 데이터를 FastAPI 엔드포인트(`@app.post("/upload")`)로 전송하기 위한 데이터 규격 조율<br>

<br>- 메인 대시보드 진입 시 `spent`, `total` 예산 데이터 및 최근 영수증 리스트 API 응답 스키마 매핑 |
| **AI 엔지니어 (Groq/Prompt)** | - Groq API가 영수증 분석 후 최종 반환하는 JSON 데이터(카테고리명, 금액 등)의 키 값이 UI의 `gr.Label` 및 `gr.Dataframe` 컬럼과 정확히 일치하도록 데이터 명세 공유 (예: '식비', '교통비' 등의 한글 카테고리 통일) |
```
