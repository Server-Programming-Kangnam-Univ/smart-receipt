## 1. 생성형 AI와의 대화 요약

생성형 AI(Gemini)와 약 30분간 대화하며, 팀 프로젝트에서 내가 담당할 기능의 구체적인 설계 방향을 결정하였다.

### 대화 흐름 요약

**[1단계] 역할 정의 및 기술 스택 결정**
- 팀 프로젝트에서 AI 쪽 역할을 맡기로 하고, 구체적으로 Groq API를 활용한 프롬프트 엔지니어링 담당으로 정함.
- OCR로 추출된 비정형 텍스트를 → 정형 JSON으로 변환하는 프롬프트 설계가 핵심 임무임을 확인.

**[2단계] 출력 JSON 구조 확정**
- AI와 함께 어떤 필드가 필요한지 논의.
- `payment_info`에 `tax`(세금)와 `discount`(할인) 항목을 추가하는 것으로 결정.
- `currency` 필드 추가: AI는 통화 코드(`KRW`, `USD` 등)만 판단하고, 환율 환산은 백엔드가 처리하는 역할 분리 방식 채택.

**[3단계] 카테고리 설계 결정**
- 무분별한 카테고리 생성을 막기 위해 6개로 고정(Enum 방식):
  `식비`, `교통비`, `생필품`, `문화생활`, `전자기기`, `기타`
- `전자기기`를 별도 분리한 이유: 팀원 및 주요 사용자가 공대생이라 전자기기 구매 빈도가 높기 때문.

**[4단계] 예외 처리 전략 결정**
- **전체 인식 실패**: `is_readable: false` 반환으로 통일. 원인 구분 없이 동일한 사용자 메시지 출력.
- **부분 인식 실패**: 전체 반려 대신, 안 보이는 항목만 `null` 처리하고 나머지 데이터는 유지. 사용자 이탈 방지 목적.

**[5단계] Hallucination 방지 전략 확정**
- 불확실한 정보는 절대 유추하지 않고 `null`/`0` 처리 강제.
- 응답 형식을 **순수 JSON만** 반환하도록 강력 지시. 마크다운 코드블록, 서술형 문장 금지.

**[6단계] Few-shot 설계 (최종 결정)**
- AI와 함께 어떤 예시를 넣을지 논의.
- 전자기기 예시에 어떤 물건이 적합한지 의견 교환 → `컴퓨터`, `케이블선`, `아두이노 키트` 채택.
- 총 4가지 케이스(정상, 전자기기 특화, 부분 훼손, 완전 실패)로 Few-shot 구성 확정.

## 2. 담당 세부 기능 명세서

### 2.1. 영수증 데이터 구조화 (JSON 파싱)

Groq API를 활용하여 비정형 영수증 텍스트를 아래 JSON 규격으로 변환하는 프롬프트 작성.

**카테고리 고정 (Enum 제한):** `[식비, 교통비, 생필품, 문화생활, 전자기기, 기타]`

> 비고: 개발팀 및 주요 타겟 사용자가 공대생임을 고려하여 '전자기기' 카테고리를 별도로 분리.

**출력 JSON 구조:**

```json
{
  "store_info": {
    "name": "스타벅스 강남점",
    "address": "서울시 강남구...",
    "phone": "02-123-4567"
  },
  "payment_info": {
    "date": "2024-06-04",
    "time": "14:30",
    "total_price": 12500,
    "currency": "KRW",
    "tax": 1136,
    "discount": 0
  },
  "items": [
    {
      "name": "아이스 아메리카노",
      "price": 4500,
      "quantity": 2,
      "category": "식비"
    }
  ],
  "quality_score": {
    "is_readable": true,
    "unrecognized_items_count": 0
  }
}
```

> 인식 불가 항목은 `null`, 금액 미인식은 `0` 처리. 날짜는 `YYYY-MM-DD`, 시간은 `HH:MM` 형식 고정.

---

### 2.2. 프롬프트 예외 처리 및 Hallucination 방지 [핵심 집중 기능]

1. **엄격한 데이터 타입 강제**
   - 날짜: `YYYY-MM-DD` 고정
   - 금액: 쉼표 제거한 `Integer` 타입 고정

2. **불확실성 처리**
   - 명확하지 않은 정보는 **절대 유추 금지** → `null` 또는 `0` 처리

3. **JSON 포맷 강제**
   - **강력 지시:** 응답에는 마크다운 코드 블록(` ```json `)이나 서술형 문장(예: "네, 분석 결과입니다")을 **절대 포함하지 마십시오.** 오직 파싱 가능한 순수 JSON 문자열만 반환해야 합니다. 이를 어길 시 시스템 오류가 발생함을 명시합니다.

4. **Few-shot 러닝 적용**
   - **Example 1 (Normal):** "스타벅스... 아메리카노 4500원" → `category: "식비"`, `total_price: 4500`
   - **Example 2 (Engineering Target):** "엘레파츠... 아두이노 키트 35,000원, 점퍼 케이블 2,500원, 조립형 컴퓨터 1,200,000원" → 모든 항목 `category: "전자기기"` (공대생 필수 품목 집중 학습)
   - **Example 3 (Partial Damage):** "이마트... [글자 훼손]... 1,000원" → `name: null`, `price: 1000` (유추 금지 원칙)
   - **Example 4 (Invalid Image):** "풍경 사진이나 낙서" → `is_readable: false`

---

### 2.3. 예외 상황 대응 프로세스

#### A. 전체 인식 실패

- **상황:** 흐릿한 영수증, 일반 사진, 악의적 메모 등 필수 정보 추출 불가
- **처리:** `quality_score.is_readable: false` 반환
- **사용자 메시지:** _"사진 인식이 실패했습니다. 또렷하거나, 선명한 영수증 사진을 올려주세요."_

#### B. 부분 인식 실패

- **상황:** 일부 항목의 가격이나 이름이 훼손되어 보이지 않는 경우
- **처리:** 인식 불가 항목만 `null` 처리, 나머지 데이터는 정상 반환 (전체 반려 X)
- **사용자 메시지:** _"해당 부분이 인식되지 않습니다. 직접 기입하거나 다시 찍어주세요."_
- **이유:** 전체 반려 시 사용자 이탈(UX 피로도 증가) 우려

---

### 2.4. 외국 영수증 / 환율 처리 (백엔드 협업)

- AI는 통화 코드(`currency: "USD"`, `"JPY"` 등)만 JSON에 추출
- 원화 환산은 **백엔드가 ExchangeRate-API를 호출**하여 처리
- 역할 분리로 AI 프롬프트의 복잡도를 낮추고 유지보수성 향상

## 3. 팀원과의 협업 포인트

| 협업 대상 | 내용 |
|-----------|------|
| **프론트엔드** | `is_readable: false` 시 재촬영/수동입력 모달 연동. `category` Enum 목록 공유. `null` 항목 감지 시 입력 칸 비우기 처리 |
| **백엔드** | 완성된 프롬프트를 Groq API 호출 코드에 삽입. 파싱된 JSON이 DB 스키마에 맞게 들어가는지 테스트. 외국 영수증의 `currency` 값을 받아 환율 API 호출 |
| **AI 2 (소비 패턴 분석)** | 내가 추출한 `items[].category`와 `payment_info.date`를 기반으로 소비 패턴 분석 AI가 자연어 쿼리를 처리할 수 있도록 데이터 규격 맞춤 |

## 4. 결론

약 30분간 생성형 AI와 대화하며 다음 사항을 단계적으로 결정하였다:

1. 출력 JSON 필드 구조 (세금, 할인, 통화 코드 포함)
2. 카테고리 6개 고정 및 `전자기기` 분리 이유
3. 전체/부분 인식 실패 처리 방식 및 사용자 메시지
4. Hallucination 방지 전략 (null 강제, JSON 순수 출력 강제)
5. Few-shot 예시 구성 (특히 공대생 맞춤 전자기기 분류)

이 명세서는 팀 프로젝트 개발 중 변경될 수 있으며, 최종 제출 시 실제 구현 내용과 다를 수 있음.
