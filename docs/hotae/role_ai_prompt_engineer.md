# 세부 기능 명세서: AI 프롬프트 엔지니어링 & OCR 최적화

## 1. 역할 개요

- **담당자:** 황호태
- **역할:** AI 1 (AI 프롬프트 엔지니어링 & OCR 최적화)
- **사용 기술/모델:** Groq API
- **핵심 목표:** 영수증 이미지에서 추출된 텍스트를 분석하여 정형화된 JSON 데이터로 변환하는 완벽한 프롬프트 설계 및 강력한 예외 처리(Hallucination 방지) 구현.

---

## 2. 주요 담당 기능

### 2.1. 영수증 데이터 구조화 (JSON 파싱)

- Groq API를 활용하여 비정형 영수증 텍스트를 사전에 정의된 엄격한 JSON 규격으로 변환하는 프롬프트 작성.
- 상품명(`name`)을 기반으로 AI가 스스로 카테고리(`category`)를 추론하여 분류하도록 지시합니다.
- **카테고리 고정 (Enum 제한):** AI가 무분별하게 새로운 카테고리를 생성하는 것을 방지하기 위해, 프롬프트 내에 아래 6가지 카테고리 중 하나만 강제로 선택하도록 명시합니다.
  - `[식비, 교통비, 생필품, 문화생활, 전자기기, 기타]`
  - _비고:_ 개발팀 및 주요 타겟 사용자가 공대생임을 고려하여 '전자기기' 카테고리를 별도로 분리하여 분석 효율을 높입니다.
- **출력될 JSON 구조 확정:**

```json
{
  "store_info": {
    "name": "스타벅스 강남점",
    "address": "서울시 강남구...", // 인식 불가 시 null
    "phone": "02-123-4567" // 인식 불가 시 null
  },
  "payment_info": {
    "date": "2024-06-04", // YYYY-MM-DD 형식 고정
    "time": "14:30", // HH:MM 형식 고정
    "total_price": 12500, // 숫자만
    "currency": "KRW", // 통화 코드 (KRW, USD, JPY 등). AI가 기호(₩, $, ¥)를 보고 판단
    "tax": 1136, // 세금 항목 (있을 경우, 없으면 0)
    "discount": 0 // 할인 금액 (있을 경우, 없으면 0)
  },
  "items": [
    {
      "name": "아이스 아메리카노",
      "price": 4500,
      "quantity": 2,
      "category": "식비"
    }
  ],
  "quality_score": {
    "is_readable": true, // 전반적인 인식 가능 여부
    "unrecognized_items_count": 0 // 인식 실패한 항목 수
  }
}
```

### 2.2. 프롬프트 예외 처리 및 환각(Hallucination) 방지 [핵심 집중 기능]

AI가 없는 정보를 지어내거나 잘못된 형식으로 출력하는 것을 막기 위해 프롬프트 내에 다음과 같은 안전장치(Guardrails)를 구현합니다.

1. **엄격한 데이터 타입 강제:**
   - 날짜는 무조건 `YYYY-MM-DD`, 금액은 `,`를 제외한 `Integer` 타입으로만 출력하도록 프롬프트에 명시.
2. **불확실성 처리 (Null / 알 수 없음):**
   - 글씨가 훼손되거나 잘려서 명확히 보이지 않는 정보는 **절대 유추하지 말고** `null` 또는 `0` 처리하도록 지시.
3. **JSON 포맷 강제:**
   - **강력 지시:** 응답에는 마크다운 코드 블록(```json)이나 서술형 문장(예: "네, 분석 결과입니다")을 **절대 포함하지 마십시오.** 오직 파싱 가능한 순수 JSON 문자열만 반환해야 합니다. 이를 어길 시 시스템 오류가 발생함을 명시합니다.
4. **Few-shot 러닝 적용:**
   - **Example 1 (Normal):** "스타벅스... 아메리카노 4500원" -> `category: "식비"`, `total_price: 4500`
   - **Example 2 (Engineering Target):** "엘레파츠... 아두이노 키트 35,000원, 점퍼 케이블 2,500원, 조립형 컴퓨터 1,200,000원" -> 모든 항목 `category: "전자기기"` (공대생 필수 품목 집중 학습)
   - **Example 3 (Partial Damage):** "이마트... [글자 훼손]... 1,000원" -> `name: null`, `price: 1000` (유추 금지 원칙)
   - **Example 4 (Invalid Image):** "풍경 사진이나 낙서" -> `is_readable: false`

### 2.3. 예외 상황 대응 프로세스 기획 (전체 실패 및 부분 실패)

#### A. 전체 인식 실패 (영수증 외 이미지, 심각한 훼손, 프롬프트 인젝션)

- **상황 정의:** 흐릿하여 글씨가 뭉개진 영수증, 일반 사진(풍경 등), 또는 악의적인 메모가 입력되어 필수 정보(상호명, 총액 등) 추출이 불가능한 경우.
- **처리 로직:** `quality_score.is_readable: false`로 통일하여 반환.
- **사용자 피드백:** _"사진 인식이 실패했습니다. 또렷하거나, 선명한 영수증 사진을 올려주세요."_

#### B. 부분 인식 실패 (일부 항목 훼손)

- **상황 정의:** 전체적인 인식은 가능하나, 일부 품목의 가격이나 이름 등 특정 정보만 오염/훼손되어 보이지 않는 경우.
- **처리 로직 (부분 허용):** AI가 남은 정보로 가격을 임의로 계산하거나 유추(Hallucination)하지 않도록 강제. 인식 불가능한 특정 항목만 `null`로 처리하고, 정상적으로 인식된 나머지 데이터는 그대로 반환.
- **사용자 피드백 연동:** 반환된 JSON에 `null` 값이 포함된 경우, 프론트엔드에서 이를 감지하여 해당 입력 칸만 비워두고 알림을 제공.
  - **출력 메시지:** _"해당 부분이 인식되어 잘 보이지 않습니다. 직접 기입하거나 다시 찍어주세요."_
- **효과:** 영수증 전체 반려로 인한 사용자 이탈(피로도 증가)을 방지하고, 유연하고 친화적인 UX를 제공할 수 있습니다.

## 3. 다른 팀원과의 협업 포인트

- **프론트엔드(UI):** `is_readable: false` 일 때 띄워줄 '재촬영/수동입력 모달 창' 연동. 카테고리 분석 시각화를 위해 제가 정의한 `category` 값 목록(enum) 공유.
- **백엔드(DB/API):** 제가 작성한 프롬프트가 Groq API를 통해 안정적으로 JSON을 반환하는지 테스트하고, 파싱된 JSON이 DB 스키마에 잘 들어가는지 확인.
- **AI 2 (검색/분석):** 제가 추출해 둔 `items` 배열의 `category`와 `date`를 기반으로, 소비 패턴 분석 AI가 쉽게 자연어 쿼리를 처리할 수 있도록 데이터 규격 맞추기.
