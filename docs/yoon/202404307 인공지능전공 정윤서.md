## 1. 생성형 AI와의 대화 요약

생성형 AI(Gemini)와 약 95분간의 심층 대화를 통해, 단순한 데이터 저장을 넘어 OCR 인식률을 극대화하고 사용자가 데이터를 자산화할 수 있는 **지능형 데이터 관리 시스템**을 설계하였습니다.

### 대화 흐름 요약

**[1단계] 역할 정의 및 데이터 저장 전략**
- 분석 결과의 휘발을 방지하기 위해 **JSON 기반 파일 DB**와 **UUID 기반 로컬 파일 시스템**을 활용한 영속성 관리 전략 수립.

**[2단계] OCR 인식 오류 진단 및 전처리 도입**
- 영수증 특유의 그림자, 흐릿한 인쇄 등으로 인한 오인식 문제를 해결하기 위해 **OpenCV** 기반의 이미지 전처리 파이프라인(Grayscale, Otsu 이진화, Morphology) 설계.

**[3단계] 데이터 스키마 및 통합 관리 설계**
- AI 추출 데이터와 수동 입력 데이터를 통합 관리하기 위한 `receipts.json` 스키마 정의 및 데이터 정합성 유지 방안 논의.

**[4단계] API 엔드포인트 확장 (CRUD & Bulk)**
- 기본적인 CRUD 외에도 대량 처리를 위한 `Bulk Upload` 및 이미지 없는 내역을 위한 `Manual Input` API 설계.

**[5단계] 시스템 안정성 및 시각화 설계**
- 디렉토리 자동 생성, 파일 쓰기 시 동시성 제어 등 안정성 확보 및 `Plotly`를 활용한 소비 분석 대시보드 시각화 구조 확정.

## 2. 담당 세부 기능 명세서

### 2.1. OCR 인식률 향상을 위한 이미지 전처리 시스템
AI 분석 전, 입력된 이미지를 최적화하여 텍스트 추출의 정확도를 극대화함.
- **그레이스케일 변환**: 색상 노이즈 제거 및 명암차 극대화.
- **Otsu 이진화**: 조명 상태에 따른 배경-글자 자동 분리.
- **모폴로지 팽창 (Dilation)**: 글자 획을 보강하여 끊어진 텍스트 연결 및 인식률 향상.

### 2.2. 이미지 및 메타데이터 영구 저장 시스템
AI 분석 결과와 원본 이미지를 연결하여 사용자가 언제든 확인 가능한 환경 구축.
- **저장 구조**: 
    - 이미지: `backend/uploads/{uuid}.png`
    - 데이터: `backend/receipts.json`
- **UUID 도입**: 파일명 중복 및 특수문자 오류 방지.

### 2.3. 데이터 관리 API 엔드포인트 개발
1. **분석 및 저장 (`POST /analyze-receipts/`)**: 이미지 전처리 → OCR 분석 → UUID 기반 저장 → JSON 업데이트.
2. **벌크 업로드 (`POST /analyze-receipts-bulk/`)**: 여러 장의 영수증을 동시에 비동기 처리.
3. **수동 입력 API (`POST /receipts/manual/`)**: 이미지 없이 내역 직접 추가 기능.
4. **이력 조회 API (`GET /receipts/`)**: 전체 내역 최신순 반환.
5. **내역 삭제 API (`DELETE /receipts/{id}`)**: JSON 데이터 삭제 시 **실제 이미지 파일도 함께 삭제(Cleanup)**하여 서버 용량 관리.

### 2.4. 소비 데이터 시각화 (Dashboard)
- **소비분석 탭**: 홈과 보관함 사이의 시각화 대시보드.
- **차트 구성**: 카테고리별 지출 합계(Bar) 및 지출 비율 분포(Pie).

### 2.5. 시스템 안정성 및 유효성 검사
- **디렉토리 자동 생성**: 서버 시작 시 필수 폴더 및 파일 부재 시 자동 생성.
- **동시성 제어**: `seek(0)` 및 `truncate()`를 활용한 안전한 파일 덮어쓰기 로직 적용.
