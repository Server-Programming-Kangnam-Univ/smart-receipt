## 1. 생성형 AI와의 대화 요약

생성형 AI(Gemini)와의 대화를 통해, 단순한 데이터 삭제를 넘어 서버 자원의 효율적 관리와 데이터 정합성을 보장하는 **안전한 삭제 시스템**을 설계하였습니다.

### 대화 흐름 요약

**[1단계] 삭제 범위 및 정책 결정**

- 사용자가 특정 영수증 내역을 삭제할 때, 데이터베이스(`receipts.json`) 기록만 지울 것인지 실제 이미지 파일까지 지울 것인지 논의.
- **결정:** 서버 용량 최적화를 위해 DB 기록과 `uploads/` 폴더 내 실제 파일을 모두 삭제하는 '완전 삭제' 정책 채택.

**[2단계] 삭제 로직 및 예외 처리 설계**

- 존재하지 않는 ID 요청 시 404 에러 반환 로직 설계.
- 파일 삭제 시 발생할 수 있는 Permission 에러나 파일 부재 상황에 대한 예외 처리(Try-Except) 방안 마련.

**[3단계] API 엔드포인트 설계**

- RESTful 원칙에 따라 `DELETE /receipts/{id}` 구조로 엔드포인트 확정.

**[4단계] 프론트엔드 연동 및 UX 고려**

- 삭제 전 사용자 확인(Confirm) 과정의 필요성과 삭제 후 UI 즉시 갱신(State Update) 방안 논의.

## 2. 담당 세부 기능 명세서

### 2.1. 영수증 내역 및 물리 파일 동시 삭제 (Cleanup)

단순 데이터 행 삭제가 아닌, 서버 스토리지를 관리하는 기능을 포함합니다.

- **DB 연동**: `receipts.json` 파일에서 요청된 `id`와 일치하는 객체를 검색하여 제거.
- **파일 정리**: 저장된 `image_url` 경로를 기반으로 `uploads/` 폴더 내의 실제 이미지 파일(`{uuid}.png`)을 찾아 `os.remove()`로 영구 삭제.
- **효과**: 불필요한 이미지 누적을 방지하여 서버 운영 비용 및 용량 관리 효율화.

### 2.2. RESTful 삭제 API 개발 (`DELETE /receipts/{id}`)

- **기능**: 특정 영수증 ID를 받아 해당 내역을 삭제.
- **처리 절차**:
  1. `receipts.json` 로드.
  2. 삭제 대상 ID 존재 여부 확인 (없을 시 `404 Not Found`).
  3. 대상 이미지 경로 추출 및 파일 삭제 시도.
  4. JSON 리스트에서 해당 항목 제외 후 파일 덮어쓰기.
  5. 성공 시 `200 OK` 또는 `204 No Content` 반환.

### 2.3. 데이터 정합성 보장 로직

- **동시성 제어**: 파일 쓰기 작업 중 발생할 수 있는 충돌을 방지하기 위해 파일을 읽고 쓰는 과정에 안전한 접근 방식(Overwrite) 적용.
- **트랜잭션 유사 처리**: 파일 삭제 실패 시 DB 삭제를 중단하거나 로그를 남겨 데이터 불일치 방지.
