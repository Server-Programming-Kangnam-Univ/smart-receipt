[백엔드 기능 추가 시 고려사항 및 개발 가이드]

본 프로젝트는 FastAPI 기반의 계층형 아키텍처(Layered Architecture)를 채택하고 있습니다. 
기능 추가 및 유지보수 시 다음 가이드라인을 준수해 주세요.

1. 계층별 역할 분담 (Layered Architecture)
- API 계층 (backend/api/): 
    * 클라이언트의 요청(HTTP Request)을 가장 먼저 받는 곳입니다.
    * 비즈니스 로직을 직접 작성하지 말고, Service 계층의 함수를 호출하여 응답을 반환하는 역할만 수행하세요.
- 서비스 계층 (backend/services/): 
    * 실제 핵심 로직(AI 호출, 데이터 처리, 파일 I/O 등)이 위치하는 곳입니다.
    * API 계층이나 다른 서비스에서 재사용 가능하도록 모듈화하여 작성하세요.
- 모델 계층 (backend/models/): 
    * 데이터의 규격(Pydantic Schema 등)을 정의합니다. 
    * 향후 데이터베이스 도입 시 이 계층에서 모델을 관리합니다.

2. AI 서비스 및 프롬프트 관리
- 모든 AI 호출 로직은 'services/ai_service.py'에서 통합 관리합니다.
- 프롬프트 수정 시 JSON 출력 형식이 깨지지 않도록 주의하고, 필요한 경우 Few-shot 예시를 포함하세요.
- API Key 등 보안 민감 정보는 절대 코드에 직접 적지 말고 '.env' 파일을 사용하세요.

3. 데이터 정합성 및 보안
- JSON 파일 DB 사용 시: 파일 쓰기 작업(f.seek(0), f.truncate()) 시 데이터가 손상되지 않도록 주의하세요.
- 보안: 새로운 파일을 생성하거나 환경 변수를 추가할 때 '.gitignore'에 등록되어 있는지 확인하여 보안 사고를 방지하세요.

4. 에러 핸들링 및 사용자 경험
- 백엔드 오류 발생 시 HTTPException을 사용하여 명확한 에러 메시지와 상태 코드를 반환하세요.
- 프런트엔드 연동 시 예외 처리를 통해 서버 응답 지연이나 오류 상황에서도 UI가 멈추지 않도록 설계하세요.

5. 문서화 및 협업
- 새로운 라이브러리를 설치하면 반드시 'requirements.txt'를 업데이트하세요.
- 중요한 구조 변경이나 기능 추가 시 'README.md'와 '세부기능명세서'를 함께 갱신하세요.

[ ] main.py에 새로운 라우터를 등록(include_router)했는가?
[ ] requirements.txt 및 .env 설정이 완료되었는가?
